# KDT 훈련과정 현황 분석 대시보드

고용24 OPEN-API의 국민내일배움카드 훈련과정 데이터를 수집해 **K-디지털 트레이닝(KDT)** 과정의 개설 현황과 변화 추이를 분석·시각화하는 개인 비영리 프로젝트입니다.

> 🚧 현재 **기획 및 API 이용 신청 단계**입니다. 진행 상황은 아래 [로드맵](#로드맵)에서 확인할 수 있습니다.

## 프로젝트 목적

고용24에서는 훈련과정을 검색할 수 있지만, 조회 시점의 정보만 보여주기 때문에 시간에 따른 변화를 파악하기 어렵습니다. 이 프로젝트는 훈련과정 정보를 주기적으로 수집·누적하여 다음과 같은 질문에 답하는 것을 목표로 합니다.

- KDT 과정은 **어떤 분야·지역·기관**에서 주로 개설되는가?
- 개설 과정 수와 모집 규모는 **시기별로 어떻게 변하는가**?
- 과정별 **모집 인원 대비 신청·등록 현황**은 어떻게 변화하는가?
- 수강료, 훈련 기간 등 과정 조건의 분포는 어떠한가?

## 사용 데이터

| 구분 | 내용 |
|---|---|
| 제공처 | 고용노동부 · 한국고용정보원 **고용24 OPEN-API** |
| 사용 API | 국민내일배움카드 훈련과정 (목록 / 과정·기관정보 / 훈련일정), 공통코드 (훈련 관련 코드) |
| 수집 주기 | 하루 1~2회 배치 수집 |
| 수집 범위 | KDT 훈련유형에 해당하는 과정 |

## 시스템 구성

```
[배치 수집기] ──(하루 1~2회)──> 고용24 OPEN-API
      │
      ▼
[데이터베이스]  원본 응답 보관 · 과정 마스터 · 일별 스냅샷
      │
      ▼
[시각화 대시보드]  DB만 조회 (API 직접 호출 없음)
```

- **수집기**: 정해진 시간에 API를 호출하고, 응답 원본과 정제된 데이터를 함께 저장합니다.
- **데이터베이스**: 변하지 않는 과정 정보와 날마다 변하는 값(모집·등록 인원, 상태 등)을 분리해 저장하여 변화 이력을 추적합니다.
- **대시보드**: 저장된 데이터만 사용하므로 사용자 조회가 API 트래픽에 영향을 주지 않습니다.

## 기술 스택 (예정)

- 수집: Python (`requests`, XML 파싱)
- 저장: PostgreSQL
- 시각화: Streamlit
- 배포: 소형 클라우드 서버 1대 (cron 스케줄링)

## 데이터 이용 원칙

- 수집한 데이터는 **통계 분석 및 시각화 목적**으로만 사용합니다.
- 화면 및 결과물에 **데이터 출처(고용24, 한국고용정보원)**를 명시합니다.
- API 인증키는 저장소에 포함하지 않으며, 환경변수로 관리합니다.
- 고용24 OPEN-API 이용 조건을 준수하며, 과도한 호출을 하지 않습니다.
